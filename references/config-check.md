# 实验配置核验：AI 必须执行的启动检查

## 目的与边界

检查预期实验条件是否与真实执行入口导出的最终生效配置一致。名字只是展示，不能从文件名猜出参数再自行宣称核验通过。检查器不运行训练、不导入模型、不修改输入文件，也不能证明导出文件来自真实进程或计算实现符合其名字。

适用训练、评估、仿真等需要配置的执行。只在实验或执行配置确实发生变化时核验；单纯聊天、文档整理、索引生成不要求启动执行器或模型。

## AI 的固定操作顺序

1. 从本轮聊天确定预期全局/局部参数、模块选择以及应保持不变的关键条件。准备 `experiment_id: "auto"` 的声明，通过 `research.py new --group ... --expected ...` 分配 EXP 编号并生成参数名及绑定该编号的 `config.expected.json` 快照。启动前必须使用 EXP 记录的 `expected_snapshot`，该文件既是命名来源，也是核验预期；保留原始声明。平铺旧记录用已有 EXP ID 新建预期声明并核对名称，不能修改旧记录/旧证据冒充原始计划。`changes` 包含所有要核对的关键条件，不仅是变化项；不能仅检查 LR 就声称完整环境与配置都已核验。
2. 确认配置字段的实际含义及映射。使用训练器真正使用的字段路径，不自行把名称相似的字段视为同一项。已有配置对象用其真实导出能力；缺少能力时先接入真实执行入口，不造一个与 expected 相同的文件替代。
3. 执行入口在默认值、配置文件、CLI 覆盖、自动推导及参数组/模块选择均完成后，从即将用于计算的实际对象导出 `config.effective.json`。保存同一次执行的 experiment_id、实际命令、代码版本/未提交差异与环境证据入口。不得把未加载的默认文件或 AI 手写的预期值称为生效配置。
4. AI 主动调用检查器。实际执行器应在开始训练/评估计算前，以该检查器的退出码作为门禁；检查通过后不再覆盖受检条件。优先同一执行进程导出并检查，避免检查一个配置、再用另一个命令启动。模型/设备构造后才能确定的值，必须在开始优化或正式评估前核验；不要通过“预检”偷跑训练。
5. 仅退出码 0 表示声明字段匹配；继续执行仍须处于用户授权范围。退出码 1/2 必须停止启动并报告差异或缺失前提，不能自动改 expected、改名、忽略返回码或缩小检查范围来获得通过。
6. 每次尝试使用独立证据目录，保存 expected、effective、receipt 及真实导出依据的路径。试验记录区分“检查通过”“实验已执行”“结果分析完成”；通过检查不代表已经运行或授权追加实验。

无法取得真实生效配置时，状态明确记为“未核验”，说明缺少哪个导出接口，不启动受影响的正式实验，也不编造通过报告。已在运行的旧实验不能凭事后导出补称启动前已核验；只能另记回溯检查。

## 输入格式

以下仅是格式示例，不是实际实验或实测配置。两个输入文件按 UTF-8 读取，并接受文件开头的 UTF-8 BOM；重复键、NaN/Infinity 与格式错误仍然拒绝。

预期声明 `config.expected.json`：

```json
{
  "experiment_id": "EXP-0001",
  "changes": {
    "optimizer.lr": 0.001,
    "optimizer.weight_decay": 0.01,
    "module_a.lr_multiplier": 0.5,
    "fusion.method": "concat",
    "training.amp": true
  }
}
```

最终生效配置的导出封装：

```json
{
  "experiment_id": "EXP-0001",
  "config": {
    "optimizer": {"lr": 1e-3, "weight_decay": 1e-2},
    "module_a": {"lr_multiplier": 0.5},
    "fusion": {"method": "concat"},
    "training": {"amp": true}
  }
}
```

- experiment_id 必须存在且一致，不能误用另一个实验的配置。执行尝试之间还须由 AI/执行器确认文件新鲜度；检查器不认证进程身份。
- `experiment_id: "auto"` 只允许提交给台账建档，由工具生成带真实编号的实验预期快照；不能直接用 auto 配置作为执行检查的实验身份。后续尝试使用 EXP 记录中固定的 expected_snapshot；不得只改字段值而不调整实验身份和名称。
- `changes` 必须为非空映射，值支持 JSON 标量、数组或对象；实际配置可包含更多字段，但这些额外字段未被检查。
- 字段是相对 config 的点分路径，例如 `optimizer.groups.0.lr` 可访问数组第一项。对象键本身含点号时须在真实导出适配层明确映射为无歧义的嵌套结构，不能让检查器猜测。
- 数字按解析后的数值精确比较，无模糊容差；`1e-3` 与 `0.001` 等价，数字字符串不等价。布尔值与 0/1 不等价。字符串区分大小写，数组顺序与对象内容须一致。
- 拒绝重复 JSON 键、NaN/Infinity、超出有限浮点范围的数值、空检查和格式错误。参数为极高精度十进制时，不应依赖二进制浮点舍入作区分；在真实配置接口中明确表示与比较精度。
- 学习率检查初始/基础值与调度规则，不拿训练中正常变化的即时 LR 去与初始 LR 比较。全局值、局部倍率、参数组最终值不可互相替代。
- Concat/Add 这类检查只确认实际导出的选择；实现是否真的正确执行对应操作仍需行为验证。

## 调用与退出码

安装目录中的直接调用：

```sh
python "$SKILL_DIR/scripts/check_config.py" \
  --expected "$ATTEMPT_DIR/config.expected.json" \
  --effective "$ATTEMPT_DIR/config.effective.json" \
  --receipt "$ATTEMPT_DIR/config.check.json"
```

新初始化项目已有相同检查器，也可调用 `python tools/check_config.py`。`SKILL_DIR` 是实际技能目录，`ATTEMPT_DIR` 是已存在的本次执行证据目录；调用前由 AI 按实际路径填写，不依赖这些变量预先存在。

- **0**：`status=passed`，声明字段匹配。
- **1**：`status=mismatch`，实验 ID 不同、字段缺失或值/类型不同。
- **2**：无效输入、读取失败，或报告不能保存。CLI 参数错误也退出 2。

报告输出到 stdout，给出逐项结果、预期值/实际值、输入路径及 SHA-256。提供 `--receipt` 时另存为新文件，拒绝覆盖旧报告，输入文件保持不变。错误报告也可保存；以 status 与退出码判断，不能把“有报告文件”当成通过。

核验不一致后修正执行器或重新讨论实验条件。条件确实改变时建立新的实验或执行记录，保留之前的预期、实际值和失败报告，不回写旧证据冒充原计划。
