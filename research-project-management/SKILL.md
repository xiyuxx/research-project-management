# 聊天驱动的科研项目管理

**写入范围**：用户要求制作 skill 不等于授权修改当前项目；只生成用户要求的 skill/模板或明确指定的新目录。既有项目默认只给审计和增量迁移方案，未经明确要求不写旧文件，不移动/删除旧产物。建档、方案、检查均不自动授予训练、评估、下载或外部提交的许可。**优先级**：项目自身的 AGENTS 或说明可以加密规则，不能放宽本节的写入范围、证据底线和执行授权；冲突时以更严的一侧为准。

## 基本流程

人通过聊天提出观察、约束、选择或问题；AI 先读项目 AGENTS、CURRENT，按需读当前组 README、相关 EXP 和 CHANGELOG，不全量预载历史。结合现有代码与证据，区分已知、假设、未核验和用户尚未决定的事项；只问实际影响下一步的分歧。给用户讲清当前条件、试过什么、结果和限制，并提出有依据的下一步；先基线加一个最小候选，不默认铺开实验矩阵。不确定记录该写成什么样时，读 `examples/first-round.md` 的一个完整回合，再按该形态落笔。

一轮形成研究条件、实际结果、明确决定或授权变化时，AI 维护相关记录，不要求用户手工操作命令；普通聊天不机械更新所有文件。只讨论方案不执行训练。讨论中出现与本轮问题无关、暂时不推进的想法，用 `python tools/research.py idea-new --slug <ascii-slug> --title "..."` 暂存到 `ideas/`，不写进 CURRENT、NEXT 或实验记录。每个下一步应说明基线、关键改动、保持条件、观察指标、可能结论与执行状态。

## 事实位置：现在、历史和单次实验

- `AGENTS.md`：AI 协作、读取、证据和执行授权规则，不保存当前参数。
- `README.md` / `SETTINGS.md`：项目介绍和公共环境、协议入口；已采用值以 CURRENT 为准，历史运行以当次快照为准。旧项目已有配置系统时直接引用真实文件，不重复发明配方。
- `CURRENT.md`：**可修改的当前快照**，记录当前选定全局配方/模块及参数与证据入口、当前问题和组、下一步、阻塞与授权边界。过期说法直接替换；其自动摘要不是实时进程存活证明。
- `CHANGELOG.md`：**只追加的研究历史**。按时间记全局和局部重要尝试、前后变化、原因、实际关键测试数据、条件/口径、EXP及日志证据、采用/暂缓/放弃及限制；没有结果只记方案/未运行。纠错另追加新条目，不改旧条目伪装历史。摘要数据可从 EXP 转录并附引用，不能独立变成另一套结果事实源。
- `experiments/GRP-*/README.md`：按共同研究问题组织一个实验系列，维护问题、起点、固定版本/共同条件、探索变量、实验索引、当下判断、不确定和下一步；历史取代过程在 CHANGELOG，不重复保存全部配置/指标。组内索引为工具生成区，人工区保留。没有主题时可暂时平铺建档，后续不能无授权静默搬动旧记录与权重。
- `EXP-*.md` 及其证据目录：单次实验完整事实与解释：问题/假设、组与对照、相对改动和保持不变、实际全局与局部参数/完整有效配置、代码版本及 dirty diff、数据/划分/初始化、环境/设备/精度/依赖、命令、评估协议、失败/续训/重试身份、日志/权重/指标与边界；生成结果区外人工内容保留。训练迭代日志交给原始产物，不手写每一步。
- `ideas/IDEA-NNN-slug.md`：只在讨论阶段、与当前方案关系不大或暂不推进的想法。记想法、动机与依据、为什么不并进当前方案、重新评估的条件；不记执行状态、参数结论或指标。它是暂存区：不进入 INDEX/NEXT/registry，不作为当前方向、下一步或证据，默认不读，用户提到旧想法或需要方向候选时再读。推进须由用户明确决定，追加 CHANGELOG 并建 EXP（或改 CURRENT），想法文件只改 `status` 与指向。
- `INDEX.md`、`NEXT.md`、`registry.json`：派生导航，不是事实源。不要创建或依赖独立研究决策文件；判断保存在对应 EXP、组 README、CURRENT 和追加式 CHANGELOG（`ideas/` 只保存未采纳的候选，不能替代这些位置）。论文引用直接链接证据。

CHANGELOG 中的全局参数（默认 LR、WD、优化器、调度、batch、训练预算、公共数据与评估）要保留各次尝试的关键测试数据、采纳与否和 EXP 引用。局部参数、模块替换/计算方式属于具体模块：每次尝试保留对应 EXP 事实，CURRENT 只保留当前选定版本/参数及依据，选择与重要失败追加 CHANGELOG。按作用范围而非参数名分类：模块专属 LR 倍率是局部；训练默认 LR 是全局。已采用全局配方可用稳定版本与不可变快照，历史 EXP 不随 CURRENT 或默认值更新而改变。消融须固定全局配方、初始化、预算、评估及模块实现/参数；共同变化时只评价整体，不强行归因。讨论过不等于尝试过，失败不等于方法无效，单点负结果不否定整条方向。

## 主题分组与名称

`experiments/GRP-001-learning-rate/README.md` 下放 `EXP-0001-optimizer-lr-1e-3.md` 及同名证据目录。EXP ID 在项目内全局唯一；组按共同研究问题，不因为同名参数强行混组。另一个主题引用原 EXP，而非复制；各运行尝试保留独立配置、日志、权重及报告，续训标注来源。组名稳定，历史引用与外部路径不因规范化而无授权搬迁。

AI 应先从聊天生成机器可读预期声明，通过台账工具从其中选择本次关键变量生成实验名；名称是展示，真实参数的权威是声明与实际配置快照，不从文件名猜配置。比如 `lr-1e-3`、`fusion-concat`、`fusion-add`；作用范围不清时带对象；名称不写 best/final/failed，不塞全配置。AI 检查组说明与对照协议，不能因同组而假设可比较。

新建组和自动命名示例（示例声明需先按实际聊天条件保存，命令不会启动训练）：

```json
{"experiment_id":"auto","changes":{"optimizer.lr":0.001,"fusion.method":"Concat","training.seed":42}}
```

```sh
python tools/research.py group-new --slug learning-rate --title "学习率探索"
python tools/research.py new --group GRP-001 --expected expected.json --title "学习率对照" \
  --name-field optimizer.lr --label optimizer.lr=lr
python tools/research.py show EXP-0001
```

建档分配实际编号，自动生成 `lr-1e-3` 等名称，将完整 changes 保存为编号化 `expected_snapshot`；
门禁使用该快照而不是文件名或原始 auto 声明。`--name-field` 只选择展示字段，不减少校验范围；
字符串值 `Concat` 和 `Add` 显示为 `concat` 和 `add`。同一条件的独立训练/重试保留各自尝试，
变化条件应另建 EXP。旧 `new --slug ...` 保留以读取/创建无预期快照的旧式记录，不能与 `--expected` 同用；
它没有自动名称绑定，实际执行前 AI 须额外登记预期、核查名字并接入门禁。`new` 只建档，不执行训练。


## 启动前的强制配置门禁

准备训练、评估或仿真时，先读 `references/config-check.md`。把本次实验声明和名字绑定，取得真实执行入口解析默认值、配置文件、CLI 覆盖和自动推导后的最终配置。正式执行走机械门禁：`run_with_gate.py` 先跑检查，只有退出码 0 才启动给定命令，1/2 直接拒绝并保留报告。

```sh
python "$SKILL_DIR/scripts/run_with_gate.py" \
  --expected "$ATTEMPT_DIR/config.expected.json" \
  --effective "$ATTEMPT_DIR/config.effective.json" \
  --receipt "$ATTEMPT_DIR/config.check.json" \
  -- python train.py --config run.yaml
```

只想核验、不启动命令时再直接调用 `check_config.py`（参数相同，不含 `--` 后的命令）；新初始化项目里两者都在 `tools/`。0 是声明字段匹配，1 是不匹配/缺字段，2 是输入无效/报告保存失败；门禁本身会在 1/2 时不运行任何命令。实际执行器必须在真实解析/推导完成后、正式计算前将退出码作为门禁，检查后不得覆盖受检条件。不可得到真实导出时记录“未核验”并停下，不能手写实际文件或用默认文件充数。检查仅核对声明字段与输入文件，不认证真实进程、代码版本、权重或实现语义，AI 需另外核实。只有检查通过且实际授权覆盖此执行才可启动。每次尝试保存独立声明、有效配置、报告与导出来源；不能将旧运行事后检查假称启动前通过。

## 完成一轮及交接

1. 用实际输出、参数/环境快照、日志、权重与评估口径完成 EXP；负结果、失败/续训保留；计划与实际、观察与推断分开。
2. 把同组证据、可比性、当前判断与未解决问题体现在组 README；可修改当前摘要，不重写历史。
3. 追加 CHANGELOG：写发生/尝试、实际数据或未运行、对照/口径、证据路径、判断及原因。重要局部尝试也记录，可链接 EXP 避免复制全部参数。
4. 根据有效证据替换 CURRENT 旧状态：当前全局/局部选定参数及依据、关注组/实验、下步、待用户决定与许可边界。旧说法不和新说法并存。讨论中与本轮无关的候选写 `ideas/`，不塞进 CURRENT 或变成隐含下一步。
5. 向用户报告具体事实、局限和一项有依据的下一步；不要编造因果、显著性、实验或论文贡献。只有解释实际闭环才标 review_status=done；结果被替换应重新确认，不能沿用旧解释。

## 初始化和兼容

```sh
SKILL_DIR=/path/to/research-project-management
python "$SKILL_DIR/scripts/init_project.py" /path/to/new-project --name "研究项目" --dry-run
python "$SKILL_DIR/scripts/init_project.py" /path/to/new-project --name "研究项目"
```

需要 Python 3.10+，无第三方依赖。台账锁按平台自动路由：Linux/macOS 用 `flock`（`experiments/.ledger.lock`），Windows 用 SQLite 写事务（`experiments/.ledger.lock.db`）；`RESEARCH_LOCK=flock|sqlite` 只用于测试或显式覆盖，同一项目不要混用。目标必须不存在或为空，符号链接/非空目标拒绝，预览不写。初始化只创建模板和工具，不创造研究结果、不训练；生成项目的 AGENTS.md 里记录初始化所用 skill 版本，便于以后判断是否需要迁移。

旧平铺 EXP 继续可读，旧 ID、命令、旧产物位置及重复标量 front matter 保持；不默认移动，不猜旧 next 是待办、已完成或约束。已有文档、参数和研究结论保留原样，迁移须由用户明确要求、先备份并验证引用；旧工具和新工具不可双写同一台账。升级 skill 不自动改已经创建的项目，用户允许后再独立迁移。旧项目补 `ideas/` 只需把本 skill 的 `assets/project/ideas/` 整个复制到项目根，不改动既有记录。

执行器/队列、多代码树、指标报表、外部数据模型溯源只在真实需求出现时接入；不默认引入数据库、任务调度或多 agent。多 seed、更多消融和论文级确认按研究证据与成本安排，不把短跑或单 seed 扩大成普遍结论。
