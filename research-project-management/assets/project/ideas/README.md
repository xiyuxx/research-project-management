# 想法池

收纳只在讨论阶段、与当前方案关系不大、暂时不推进的想法。这里是**暂存区**，不是计划、不是决定、也不是证据：写进来不等于采纳，不等于会排进下一步。

## 什么放这里

- 讨论中冒出来、但与本轮问题无关，或者暂时没有依据、预算、前置条件去做的方向。
- 方法替换、数据或评估口径的候选，值得留一句话但还不该进实验记录。
- 用户说「先记着」的东西。

## 什么不放这里

| 内容 | 正确位置 |
| --- | --- |
| 当前方案的下一步、待决定事项 | `CURRENT.md` 人工区；派生任务见 `NEXT.md` |
| 已经决定要做的实验 | `experiments/` 下 `status=planned` 的 EXP |
| 已经跑过的实验、参数与结果 | EXP 与运行产物 |
| 影响当前配方或方向的决定及理由 | `CHANGELOG.md` + 对应 EXP |

放进来不等于承诺。想法没有执行状态，不需要门禁，也不会被 `reindex` 收录：`INDEX.md`、`NEXT.md`、`registry.json` 只派生 EXP。

## 写一份想法

```sh
python tools/research.py idea-new --slug moe-fusion --title "用 MoE 路由替代 concat 融合"
```

输出 `ideas/IDEA-0001-moe-fusion.md`。编号在项目内全局唯一、跨会话不重复；正文骨架来自 `_template.md`，人工区直接改。手工新建同样可以，但文件名必须是 `IDEA-NNNN-slug.md`，`id` 与文件名一致。

`status` 只有三个值，都不是执行状态：

- `parked`：暂存。新建默认值。
- `promoted`：已经转成实际工作，文件里要有指向 EXP 编号或 CHANGELOG 条目的行。
- `dropped`：确认不做，保留文件与一句原因，不改写原想法。

## 从想法到实际工作

想法要离开这里，必须由用户明确决定，并留下可追溯的落点：

1. 追加 `CHANGELOG.md`：决定、理由、以及实际做法与原想法的差异。
2. 需要实验时用 `research.py new` 正常建档并走配置门禁；不需要实验时改 `CURRENT.md` 的方向或配方。
3. 把该想法的 `status` 改成 `promoted`，加一行指向 EXP 编号或 CHANGELOG 条目。

不要复制 EXP 内容回想法文件，也不要用想法文件代替 EXP 或决定记录。放弃时保留原想法和原因，另写一行结论，不删改旧文字。

## 读取约定

AI 默认不读 `ideas/`；只有当用户提到以前的想法、或需要方向候选时才读相关文件。汇报时把它们说成「暂存的想法」，不能说成当前方案、下一步或已有证据。
